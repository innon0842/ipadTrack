# iPad Trackpad

**iPad를 Mac의 무선 트랙패드로 사용하는 Swift 기반 앱입니다.**

iPad의 멀티터치 입력을 로컬 네트워크로 전달하고, Mac에서 마우스·키보드 이벤트로 변환합니다. 클라이언트와 서버를 함께 구현하며 제스처 인식, 기기 간 통신, 커서 움직임 보정과 기능별 모듈 구성을 다룬 포트폴리오 프로젝트입니다.

> 개발·시연용 실험 프로젝트입니다. 현재 인증·페어링·암호화가 구현되어 있지 않으므로 신뢰할 수 있는 로컬 네트워크에서만 사용하세요. 서버를 인터넷에 노출하지 말고, 사용 후 앱을 종료하세요.

## 1. 주요 기능

| iPad 제스처 | Mac 동작 |
| --- | --- |
| 한 손가락 이동 / 탭 | 커서 이동 / 왼쪽 클릭 |
| 두 손가락 이동 / 탭 | 스크롤 / 오른쪽 클릭 |
| 두 손가락 좌우 스와이프 | 이전·다음 페이지 |
| 세 손가락 이동 | 드래그 |
| 네 손가락 위로 스와이프 | Mission Control |

4단계 감도 설정, 라이트·다크 테마, 조작 상태 표시를 지원합니다. 페이지 이동과 Mission Control은 앱·시스템 단축키 설정에 따라 동작이 달라질 수 있습니다.

## 2. 기술 스택

| 영역 | 사용 기술 |
| --- | --- |
| 공통 | Swift, Network framework, UDP, Observation |
| Client | SwiftUI, UIKit, UIGestureRecognizer, UIViewRepresentable |
| Server | SwiftUI, AppKit, CoreGraphics, QuartzCore |
| 실행 환경 | iPadOS 26.5+, macOS 26.5+ |
| 빌드 확인 | Xcode 27.2 |

외부 패키지는 사용하지 않습니다. 멀티터치와 기기 간 동작 확인에는 실제 iPad와 Mac이 필요합니다.

## 3. 동작 구조

```text
iPad 제스처 인식 → 상대 이동량·명령 생성 → UDP 전송
                                             ↓
Mac 입력 이벤트 ← 커서·키보드 서비스 ← DTO 디코딩·명령 라우팅
```

통신에는 12바이트 페이로드를 사용합니다.

| 명령 코드 | 예약 필드 | 첫 번째 값 | 두 번째 값 |
| --- | --- | --- | --- |
| UInt16 · 2바이트 | UInt16 · 2바이트 | Float · 4바이트 | Float · 4바이트 |

현재 Apple 기기의 little-endian 형식을 사용하며 서버에서 길이와 숫자 유효성을 검사합니다. UDP/IP 헤더는 위 크기에 포함하지 않습니다.

## 4. 주요 구현 내용

- **상대 이동량 기반 제어:** 절대 터치 좌표 대신 `dx`, `dy`를 전송해 손가락을 다시 올릴 때 커서가 터치 위치로 이동하지 않도록 구성했습니다.
- **SwiftUI·UIKit 연결:** 화면은 SwiftUI로 구성하고, 손가락 수별 제스처는 UIKit에서 인식해 `UIViewRepresentable`로 연결했습니다.
- **커서 움직임 보정:** 이동량에 따른 가속, 소수점 이동량 누적, 속도 예측과 관성 감속을 구현했습니다.
- **물리 마우스와 공존:** 입력이 유휴 상태가 되고 관성이 끝나면 물리 마우스에 커서 제어권을 반환합니다.
- **책임 분리:** 네트워크 수신, DTO 디코딩, 명령 라우팅, 실제 입력 제어를 분리했습니다.

커서 타이머의 목표 간격은 약 8.33ms입니다. 실제 120Hz 입력이나 특정 지연 시간을 보장하는 측정 결과는 아닙니다.

## 5. 프로젝트 구조

```text
.
├── iPadTrackpadClient/
│   └── iPadTrackpadClient/
│       ├── App/
│       ├── Networking/
│       ├── Models/
│       └── Features/Trackpad/
│           ├── Appearance/
│           ├── Input/
│           └── Components/
└── MacTrackpadServer/
    ├── Docs/
    ├── Tests/
    └── MacTrackpadServer/
        ├── App/
        └── Modules/
            ├── Server/       # 조립·설정·컨트롤러·상태·화면
            ├── Networking/   # UDP 서비스·DTO·명령 모델
            ├── Cursor/       # 커서·클릭·스크롤·드래그
            ├── Keyboard/     # 키보드 이벤트
            └── SystemInfo/   # 화면·커서 위치·IP 조회
```

서버는 각 기능 모듈 내부에 필요한 계층을 배치했습니다. 모듈은 하나의 Xcode 앱 타깃 안에서 폴더로 구분하며, 별도 패키지나 프레임워크는 아닙니다.

## 6. 실행 방법

1. 두 기기를 서로 통신할 수 있는 동일한 신뢰 네트워크에 연결합니다.
2. 각 폴더의 `.xcodeproj`를 열고 **Signing & Capabilities → Team**을 자신의 개발 팀으로 변경합니다.
3. 각 앱 타깃의 **Info**에 `NSLocalNetworkUsageDescription`을 추가하고 로컬 네트워크 사용 목적을 입력합니다. 현재 프로젝트 설정에는 해당 키가 명시되어 있지 않습니다.
4. Mac 서버를 실행하고 **시스템 설정 → 개인정보 보호 및 보안 → 접근성**에서 `MacTrackpadServer`를 허용합니다.
5. 클라이언트의 `Networking/UDPSender.swift`에서 `serverIP`를 Mac의 IPv4 주소로 변경합니다.
6. iPad에서 클라이언트를 실행하고 커서 이동과 제스처를 확인합니다.

기본 포트는 UDP `12345`입니다. 현재 자동 검색과 IP 입력 UI가 없어 IP 변경 후 다시 빌드해야 합니다. 서버의 IP 표시는 `en0` 기준이므로 다른 인터페이스를 사용한다면 macOS 네트워크 설정에서 확인하세요.

사용 후에는 서버 앱을 완전히 종료하거나 Xcode에서 실행을 중지하세요.

## 7. 검증 및 현재 한계

클라이언트 시뮬레이터 빌드와 서버 macOS 빌드를 확인했습니다. 아래 스크립트는 실제 입력 이벤트 없이 패킷 호환성, 잘못된 데이터 거부, localhost UDP 수신과 서버 중지·재시작을 검증합니다.

```sh
./MacTrackpadServer/Tests/run-checks.sh
```

현재 남아 있는 주요 한계는 다음과 같습니다.

- 접속 기기 인증·암호화, 접속 수·수신량 제한이 없습니다.
- 클라이언트의 연결됨 표시는 서버 응답을 확인한 결과가 아닙니다.
- UDP 해제 패킷 유실 시 클릭·드래그의 눌림 상태가 남을 수 있습니다.
- 손바닥 필터는 접촉 반경 기반이며 시스템 제스처와 충돌할 수 있습니다.
- 실기기별 동작, 다중 모니터, 입력 지연과 CPU 사용률은 추가 검증 대상입니다.
